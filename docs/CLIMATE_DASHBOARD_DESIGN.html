UN / World Bank Dashboard Standards Applied

The design draws on established international practices:

  • World Bank: Hierarchical structure — overview metrics first, then drill-down by filters (country/region, year, indicator)
  • UN SDG: Category-based browsing with thematic icons (Land, Water, Ecosystems, Climate)
  • IPCC: M.A.D.E principle (Message, Audience, Design, Evaluation); clear intent; accessible colors (no rainbow); colorblind-friendly palettes
  • DataBank / Open Data: Interactive maps, filter panels, embeddable visualizations, mobile-optimized

3. Module Dropdown (One at a Time)

Use a dropdown to switch between the seven climate modules. Do not display all indicators from all modules at once — when one module is selected, only that module's content is shown:

  • Land Use / Land Cover Classification
  • Coastal changes
  • Assessing Flood Risk from Past Weather
  • Climate indicators
  • Marine heat waves
  • Coral reef mapping
  • Soil health

Example: When "Coastal changes" is selected, only coastal-related indicators, maps, and charts are displayed. No mixing with Land Use, Flood Risk, or other modules.

4. Map and Context Panel (Module-Specific)

  • Map: Shows only the selected module's layers (e.g. Coastal changes → coastal erosion/accretion map)
  • Context panel: KPIs and charts for the selected module only
  • Single legend only: Do not duplicate legends — use one legend per module, either on the map overlay or in the context panel, not both. Avoid redundant entries (e.g. "High Erosion" or "Stable" appearing twice).
  • No mixing: Switching between modules replaces all content; no overlap of indicators

6. Shared Controls and Filters

Reuse existing controls: AreaSelect (province, area council), YearSelect, AttributeFilterSelect, DownloadDataDialog. Add a Time range control for modules that need multi-year or seasonal views.

7. Real-World Accurate Text

All labels, metrics, legends, and dropdowns should use actual real-world accurate text — no placeholders or gibberish. Examples:

  • KPI subtitles: "Vanuatu national average", "vs. 30-year baseline", "+1.07 mm/yr trend", "per capita 2022"
  • Data types: "Sea surface temperature", "Climate indicators", "Land use / land cover"
  • Date ranges: "Last 12 months", "2020–2024", "All data"
  • Legends: One legend per module — no duplicates on map and panel. Proper units (e.g. °C, mm/yr, tCO2/cap) and valid ranges (e.g. -1.5 to 1.5 °C). Fix typos (e.g. "Erorotion" → "Erosion").
  • Region: "Vanuatu" (not "Vanuatu rand" or similar)

8. Visual Hierarchy and Theming

  • Use a distinct accent for Climate mode (e.g. green/teal) vs Disaster (amber/red)
  • Keep the same glass-style header and sidebar styling
  • Use icons per module (LuTreePine, LuWaves, LuDroplets, LuThermometer, LuFish, LuSprout)

9. Progressive Rollout

  1. Phase 1: Enable Climate mode with the full layout (map + sidebars) instead of the placeholder
  2. Phase 2: Add one or two modules first (e.g. LULC + Climate indicators)
  3. Phase 3: Add remaining modules as data and APIs become available
  4. Phase 4: Add further modules as data becomes available

10. Recommended Architecture

  1. Remove the full-screen placeholder — show the same three-column layout in Climate mode
  2. Add ClimateSection — module dropdown; when selected, show only that module's layers and context panel content
  3. Use a "Climate" cluster — or a dedicated cluster per module for datasets
  4. Extend ContextPanelContent — add climate-specific content based on active module
  5. Reuse map components — VectorLayers, PMTilesLayers, TabularLayer for climate layers
  6. Add a Climate mode badge — small header badge for quick recognition

11. Backend: Disaster vs Climate Availability

Vector and PMTiles datasets have two checkboxes in the admin:

  • Available in Disaster — when checked, the dataset appears in Disaster mode
  • Available in Climate — when checked, the dataset appears in Climate mode

Both checked = available in both. One only = that mode only. The API filters by scenario (disaster/climate) when returning datasets.

12. Data Model Considerations

  • LULC: Raster or vector, with class codes and labels
  • Coastal / Flood / Marine / Coral: Raster or vector, possibly PMTiles for large areas
  • Climate indicators: Time series + optional raster for spatial view
  • Soil health: Vector or raster with attributes
